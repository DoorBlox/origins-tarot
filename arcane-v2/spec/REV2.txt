# PART 0 — GLOBAL IMPLEMENTATION NOTES

## 0.1 Conventions

- **Cooldowns** are written in seconds. Multiply by **20** to get ticks.
- **`[D]`** = pure Origins 1.4.1 datapack JSON.
- **`[S]`** = requires KubeJS or a scoreboard helper. A fallback is stated where applicable.
- **`[D/S]`** = core effect is datapack-feasible; a sub-effect needs scripting.
- **`multiply_total`** = percentage modifier of final value.
- **Amplifier 0** = level I, **amplifier 1** = level II, etc.
- Damage values in hearts; 2 damage = 1 heart.

## 0.2 REQUIRED CHANGE — Offensive abilities target players too

**Every offensive ability in this document that previously targeted only `#tarot:hostile` now also affects enemy players.** The tag remains the same, but the implementation uses a **combined target selector**: `#tarot:hostile` OR `minecraft:player` (excluding the power holder and their teammates).

**Scoping rules:**
- **Offensive abilities** (damage, debuffs, forced targeting, negative status effects) → target **hostile mobs AND enemy players**.
- **Ally-affecting abilities** (healing, buffs, positive status effects) → target **self AND same-team players only**.
- **Mob-specific abilities** (undead-only, passive-mob-only, villager-specific) → keep their mob restriction unchanged.
- **Pacification / crowd-control** that removes a mob's ability to act → applies to hostile mobs AND enemy players where possible.

**Implementation for command AI:**
- For datapack powers using `entity_condition` or `bientity_condition`: use `origins:or` combining `origins:in_tag` (tarot:hostile) and `origins:entity_type` (minecraft:player with team check).
- For KubeJS abilities: extend target scans from `level.getEntitiesOfClass(Monster.class, aabb)` to `level.getEntitiesOfClass(LivingEntity.class, aabb).filter(e -> e instanceof Monster || (e instanceof ServerPlayerEntity p && !isTeammate(p, holder)))`.

## 0.4 Common power patterns

**Pattern A — Cooldown-gated active:** `origins:multiple` with `origins:cooldown` + `origins:active_self` gated by `resource == 0`.

**Pattern B — Damage reduction:** `origins:modify_damage_taken` with `multiply_total: -X`.

**Pattern C — Damage boost:** `origins:modify_damage_dealt` or `origins:modify_projectile_damage`.

**Pattern D — Area effect (new target rule):** `origins:area_of_effect` with `bientity_condition` = `origins:or[in_tag(tarot:hostile), entity_type(player) with team check]`.

**Pattern E — Conditional attribute:** `origins:conditioned_attribute` with `tick_rate: 20`.

**Pattern F — Reactive:** `self_action_when_hit`, `attacker_action_when_hit`, `target_action_on_hit`.

**Pattern G — Timer:** `origins:action_over_time` with `interval` in ticks.

**Pattern H — Decoy armor stand:** `armor_stand` with `{Marker:1b, Invisible:1b, NoGravity:1b, Tags:["tarot_decoy"]}`.

**Pattern I — Lethal-hit cancellation `[S]`:** KubeJS `LivingEntityDamageEvent`.

**Pattern J — Multi-target on-tick scan `[S]`:** KubeJS throttled to 5-tick intervals, cap 50 entities.

## 0.5 Progression integration

File naming: `tarot:<card>/<seq>_<ability_name>` (e.g., `tarot:fool/9_spirit_vision`). The progression system grants/revokes powers by sequence.
