# PART 0 — GLOBAL NOTES + NEW MECHANICS

## 0.1 Progression Timeline

| Seq | State | Mechanism |
|---|---|---|
| **9** | Start | 1 pathway unlocked. **1 ability slot.** Seq 9 auto-active. |
| **8** | Progress | 1 pathway. **2 slots.** Seq 9, 8 auto-active. |
| **7** | Progress | 1 pathway. **3 slots.** Seq 9-7 auto-active. |
| **6** | Progress | 1 pathway. **4 slots.** Seq 9-6 auto-active. |
| **5** | Progress | 1 pathway. **5 slots.** Seq 9-5 auto-active. |
| **4** | **2nd pathway unlocks** | 2 pathways. **6 slots.** Player must allocate sequences from either pathway. |
| **3** | Slot choice | 2 pathways. **7 slots.** |
| **2** | Slot choice | 2 pathways. **8 slots.** |
| **1** | **Resonance activates** | Slots abolished. **Full Resonance kit** for Seq 9-0 auto-active. |
| **0** | Resonance capstone | Included in Seq 1 Resonance suite. |

**Slot formula:** `slots = 10 - current_sequence`. Confirmed at Seq 4 = 6 slots.

## 0.2 Slot System Summary

- Each **slot** holds **ONE (pathway, sequence) pair**.
- Selecting a (pathway, sequence) grants **ALL abilities** from that sequence.
- **Before Seq 4:** Slots are trivially auto-filled with the single pathway's sequences in order.
- **At Seq 4:** 2nd pathway unlocks. Player has 6 slots and 12 possible sequences (6 per pathway). They choose which 6.
- **At Seq 3:** 7 slots, 14 possible sequences (7 per pathway).
- **At Seq 2:** 8 slots, 16 possible sequences (8 per pathway).
- **At Seq 1:** Slots no longer gate. All **Resonance Seq 9-0 abilities** become active.

## 0.3 Target Rules (unchanged from Rev 2)

- **Offensive abilities** (damage, debuffs, forced targeting, negative effects) target **`#tarot:hostile` AND enemy players**.
- **Ally abilities** (healing, buffs, positive effects) target **self AND same-team players**.
- **Mob-specific abilities** (undead-only, passive-mob-only, villager-specific) keep their mob restriction unchanged.
- Team check: use `origins:in_tag` (tarot:hostile) OR (`origins:entity_type` player + team ≠ holder's team).
- KubeJS: `level.getEntitiesOfClass(LivingEntity.class, aabb).filter(e -> e instanceof Monster || (e instanceof ServerPlayerEntity p && !isTeammate(p, holder)))`.

## 0.4 Required tags (unchanged from Rev 2)

`#tarot:hostile` · `#tarot:undead` · `#tarot:passive` · `#tarot:natural_stone` · `#tarot:sanctified_ground` · `#tarot:books` · `#tarot:meat` · `#tarot:unphasable` · `#tarot:decoy` · `#tarot:shadow_minion` · `#tarot:shadow_sin`

## 0.5 Fool's weakness (updated)

**Spiritual Expenditure:** Sprinting and Elytra cost **25% more exhaustion** (was 40%).

# PART C — SLOT SYSTEM SPECIFICATION

## C.1 Data model

Each player has a persistent **slot array** stored in player persistent data (`tarot_slots`):

```
{
  "slots": [
    { "pathway": "tarot:fool", "sequence": 9 },   // slot 1
    { "pathway": "tarot:fool", "sequence": 8 },   // slot 2
    { "pathway": null, "sequence": null },         // empty
    ...
  ],
  "max_slots": 6,
  "mode": "single" | "slot" | "resonance"
}
```

**Field definitions:**
- `pathway`: Origin ID (e.g., `tarot:fool`, `tarot:hanged_man`) or `null` for empty.
- `sequence`: Integer 0-9 or `null` for empty.
- `max_slots`: `10 - current_sequence` (calculated on Sequence change).
- `mode`: `"single"` (Seq 9-5), `"slot"` (Seq 4-2), `"resonance"` (Seq 1-0).

## C.2 Modes

### Mode: `single` (Seq 9-5)
- Player has **one pathway** (their starting Arcana).
- Slots auto-filled in order: Seq 9 → Seq 8 → ... → Seq 5 in slots 1-5.
- **All abilities from Seq 9-5 are active.** No choice needed.
- No player interaction with slots.

### Mode: `slot` (Seq 4-2)
- Player has **two pathways** (starting Arcana + registered second).
- Both pathways are at the **same sequence** as the player (progressed together).
- **Available sequences:** For each pathway, Seq 9 through the player's current sequence.
  - Example at Seq 4: Fool has {Seq 9, 8, 7, 6, 5, 4}, Hanged Man has {Seq 9, 8, 7, 6, 5, 4} = 12 options.
- **Slots:** `10 - current_sequence` (6 at Seq 4, 7 at Seq 3, 8 at Seq 2).
- Player **must pick** which sequences to activate, up to `max_slots`.
- **Only the abilities within activated sequences are usable.**

### Mode: `resonance` (Seq 1-0)
- Slots are **ignored**.
- **All Resonance abilities (Seq 9-0) become active automatically.**
- Individual pathway abilities are **disabled**.
- Player no longer has a slot UI.

## C.3 Slot commands

Provide via KubeJS command:

**`/tarot slots`**
- Opens slot management GUI OR prints a chat summary showing current slot assignments.

**`/tarot slot <slot_number> <pathway> <sequence>`**
- Assign a sequence to a specific slot.
- Example: `/tarot slot 1 tarot:fool 9` → assigns Fool Seq 9 to slot 1.
- Validates: pathway is one of the player's registered paths, sequence is unlocked, slot_number ≤ max_slots.

**`/tarot slot <slot_number> clear`**
- Clears a specific slot.

**`/tarot slot auto`**
- Auto-fills slots with the highest available sequences from the primary pathway (useful default before player customizes).

**`/tarot slot swap <slot_a> <slot_b>`**
- Swaps two slots for convenience.

**`/tarot reset`**
- Resets all slots to defaults (primary pathway sequences in order). Useful if the player accidentally misconfigures.

**Permission:** Only the player themselves can run these commands on their own slots (no admin override needed for gameplay).

## C.4 Grant/revoke mechanism

**On any slot change (assignment, clear, swap, reset):**

1. **Revoke all pathway-related powers** from the player:
   - For each sequence (9-0) of each pathway, call `power revoke <player> tarot:<pathway>/<seq>_*`.
   - Also revoke the Resonance powers if in slot mode (they should never be active in slot mode).

2. **Iterate through `slots[]`:**
   - For each non-empty slot `{pathway, sequence}`, grant all powers belonging to that sequence:
     - `power grant <player> tarot:<pathway>/<seq>_ability1`
     - `power grant <player> tarot:<pathway>/<seq>_ability2`
     - etc.

3. **Update HUD** (if present): render current slot assignments in a custom HUD bar.

**On Sequence change:**

- When entering Seq 4 (mode transitions from single → slot):
  - Increase `max_slots` to 6.
  - Keep existing slots 1-5 (Seq 9-5 of primary pathway).
  - Add empty slot 6.
  - Notify player: *"Second pathway unlocked. You now have 6 slots. Use `/tarot slot` to customize."*
- When reaching Seq 3:
  - Increase `max_slots` to 7.
  - Notify player.
- When reaching Seq 2:
  - Increase `max_slots` to 8.
- When reaching Seq 1 (mode transitions from slot → resonance):
  - **Revoke all individual pathway powers.**
  - **Grant all Resonance powers** for Seq 9-0 (all 10 Resonance abilities in the pair).  - Clear slots (no longer relevant).
  - Notify player: *"Resonance achieved. The two pathways have merged."*

## C.5 Enforcement (preventing unassigned abilities)

Two enforcement layers (use both):

**Layer 1 — Grant/revoke:**
- Player literally does not have the power granted if their sequence isn't slotted.
- This is the primary enforcement. No `condition` check needed.

**Layer 2 — Runtime guard (belt-and-suspenders):**
- For `[S]` KubeJS abilities, add a guard at the top of every event handler:
  ```javascript
  function isSequenceActive(player, pathway, sequence) {
    const slotData = player.persistentData.tarot_slots;
    return slotData.slots.some(s => s.pathway === pathway && s.sequence === sequence);
  }
  ```
- If not active, return early. Prevents ghost triggers from stale cooldowns or persistent effects.

**Layer 3 — Passive cleanup on transition:**
- When switching to resonance mode, actively `clear_effect` any lingering passive buffs (Resistance I from Shadow of Degeneration, etc.) that came from individual abilities.
- Same when a slot is cleared.

## C.6 Transition sequence

### At Seq 5 → 4 (single → slot):

1. Grant access to the 2nd pathway's origin (should already be pre-registered).
2. Set `mode = "slot"`.
3. Set `max_slots = 6`.
4. Slots remain filled with primary pathway Seq 9-5 (5 slots).
5. Slot 6 is empty.
6. Display notification with a tutorial popup explaining the slot system.
7. Optionally auto-fill slot 6 with the highest available sequence from either pathway (player can override).

**IMPORTANT:** The 2nd pathway's sequences 9-4 must be **unlocked but not granted** at this point. The origin should have access but the powers are not active until slotted.

### At Seq 4 → 3 → 2 (slot count increases):

1. Set `max_slots = 10 - current_sequence`.
2. Do NOT auto-fill new slots (let player choose).
3. Display notification of new slot count.

### At Seq 2 → 1 (slot → resonance):

1. Revoke ALL individual pathway powers (Seq 9-0 of both pathways).
2. Set `mode = "resonance"`.
3. Clear `slots[]` (set all to `{pathway: null, sequence: null}`).
4. Grant all Resonance abilities for the pair (Seq 9-0, 10 abilities).
5. Clear lingering passive effects from previous abilities.
6. Play a dramatic visual (particle burst, sound, chat message).
7. Display notification: *"Your two pathways have merged. You have achieved Resonance."*

### At Seq 1 → 0 (resonance → resonance capstone):

1. Nothing special — Seq 0 Resonance ability is already in the Resonance kit granted at Seq 1.

## C.7 Edge cases

**Player relogs or dies:**
- Slot data persists in player persistent data.
- On respawn/login, re-apply the grant/revoke cycle to ensure the powers match the slots.
- Use a `PlayerRespawnEvent` + `PlayerLoggedInEvent` KubeJS hook.

**Player attempts to slot a sequence they don't have:**
- Reject with error message: *"You have not unlocked Sequence X in Pathway Y."*

**Player attempts to slot more sequences than slots:**
- Reject with error message: *"All slots are full. Clear one first."*

**Player at Seq 4 has both pathways at same Seq:**
- Correct — both pathways progress together.

**Player at Seq 2 has 8 slots and 16 available sequences:**
- Correct — they pick 8 of 16.

**Player reaches Seq 1 without ever customizing slots:**
- At the transition, slots are auto-cleared and Resonance is granted. Their previous slot choices are discarded (they get the better Resonance kit anyway).

**Player reaches Seq 0 while at Seq 1:**
- No change — Resonance already active.

**Transitioning while abilities are on cooldown:**
- Cooldowns are revoked with the abilities (cooldown data is per-power, not per-player, so revoking the power resets it).
- When re-granted (or when Resonance activates), cooldowns start fresh.

## C.8 UI recommendations

Provide a HUD overlay (KubeJS + client-side mod, e.g., `Cardinal Components` or `Origins` HUD hooks) showing:
- Current mode (single/slot/resonance)
- Slot count: `N / max_slots` filled
- List of active (pathway, sequence) pairs with icons or abbreviations (e.g., "F9" for Fool Seq 9)

Alternatively, provide `/tarot slots` chat output listing the current configuration.

**Suggested chat format:**
```
═══════ TAROT SLOTS (6/6) ═══════
[1] Fool 9    [2] Fool 8    [3] Fool 7
[4] HM   9    [5] HM   8    [6] HM   7
════════════════════════════════
Mode: SLOT · Sequence 4
```

## C.9 KubeJS integration pseudocode

```javascript
// On player login/respawn:
PlayerEvents.loggedIn(event => refreshSlots(event.player));
PlayerEvents.respawned(event => refreshSlots(event.player));

// On sequence change:
// (called by progression system)
function onSequenceChange(player, oldSeq, newSeq) {
  const oldMax = 10 - oldSeq;
  const newMax = 10 - newSeq;
  
  // Handle mode transitions
  if (oldSeq >= 6 && newSeq <= 5 && newSeq > 1) {
    // Enter slot mode at Seq 4
    // (only fires when newSeq === 4)
  }
  if (newSeq === 4) enterSlotMode(player);
  if (newSeq === 1) enterResonanceMode(player);
  
  // Update max slots
  player.persistentData.tarot_maxSlots = newMax;
}

function enterSlotMode(player) {
  player.persistentData.tarot_mode = "slot";
  player.persistentData.tarot_maxSlots = 6;
  // Keep existing slots 1-5 filled with primary pathway
  // Slot 6 empty
  refreshSlots(player);
  player.sendMessage("Second pathway unlocked. Use /tarot slot to configure.");
}

function enterResonanceMode(player) {
  player.persistentData.tarot_mode = "resonance";
  // Revoke all individual pathway powers
  revokeAllPathwayPowers(player);
  // Grant all Resonance powers
  grantAllResonancePowers(player);
  // Clear slot data
  player.persistentData.tarot_slots = emptySlots();
  player.sendMessage("Your paths have merged. Resonance achieved.");
}

function refreshSlots(player) {
  const mode = player.persistentData.tarot_mode;
  if (mode === "resonance") return; // handled elsewhere
  
  // Revoke all pathway powers
  revokeAllPathwayPowers(player);
  
  // Grant powers for each filled slot
  const slots = player.persistentData.tarot_slots;
  slots.forEach(slot => {
    if (slot.pathway && slot.sequence !== null) {
      grantSequencePowers(player, slot.pathway, slot.sequence);
    }
  });
}

function revokeAllPathwayPowers(player) {
  // Iterate all 22 pathways × 10 sequences × N abilities
  ALL_POWERS.forEach(powerId => {
    if (playerHasPower(player, powerId)) {
      revokePower(player, powerId);
    }
  });
}

function grantSequencePowers(player, pathway, sequence) {
  const powers = POWERS_BY_SEQUENCE[pathway][sequence] || [];
  powers.forEach(powerId => grantPower(player, powerId));
}
```
